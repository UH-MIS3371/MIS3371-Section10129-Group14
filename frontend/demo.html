Transaction demo

Watch one order travel through every layer: browser, API Gateway, Lambda, business rules, DynamoDB and back. Every step makes the real call.

Pick an order

A valid order really changes your paper account's cash and holdings. The other examples are rejected and change nothing. Press Start demo, then Next step or the right arrow key.

Or run every test case at once

SayEach row sends a real request to the deployed API and compares the answer with what the business rules say should happen: valid, invalid, boundary, business-rule, retrieval and error cases.

The run first resets your paper account to $10,000.00 so every starting condition is known, then places real orders. Rejected orders are saved as Rejected records. As a guest, the same cases run in your browser and nothing is sent to AWS.

    Recording guide: what to show, in order
    1. Open the deployed site and sign in. Say that the page is hosted on AWS Amplify and talks to API Gateway, Lambda and DynamoDB.
    2. Pick Valid order and press Start demo. Step through the seven stages. Stop on step 7 and read out the confirmation number.
    3. Retrieve it: on step 6 the demo reads the saved record back with that number. Then open Activity, paste it into Check transaction status, and show the same record.
    4. Invalid and business-rule cases: run Quantity 0, Not enough cash and Sell shares you don't own. Read the rejection reason aloud each time, and point out that the order is saved as Rejected.
    5. Boundary cases: run the test matrix and point at T11 (largest affordable Buy accepted) and T12 (one more share rejected).
    6. Close: scroll the matrix, say how many cases passed, and say the data you saw came from DynamoDB, not from the browser.
